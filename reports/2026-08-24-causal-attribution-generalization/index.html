Does the causal structure earn its keep?

An attribution study of the feat/v2 architecture for O-RAN xApp conflict mitigation. The study separates the causal structure from the dense residual, and tests it on three environments at the prediction level and the decision level. This report states what changed from the conference proof-of-concept, the measured results, the decisions taken, the open problems, and the recommended next steps.

Summary for the reader

What the study found

  1. The causal structure earns its keep — this is the solid result. A model that uses only the discovered causal structure, with the dense residual off, predicts the next state better than a plain neural network by 27%, 48%, and 67% across Env I, III, and IV. The gain grows as the environment gets more complex.
  2. The discovered graph generalises better than the true graph out of distribution. On held-out out-of-distribution data the discovered structure beats the environment's true adjacency by 1.2×, 3.8×, and 5.5×. The margin is largest in Env IV, which has a hidden confounder that the true observed-node graph cannot represent.
  3. The bounded residual is not doing the work. The residual adds a small help in Env I (+11%) and is net harmful in Env III and Env IV. The earlier "residual collapse" worry does not hold at the prediction level.
  4. The decision-level result is not settled. The utility gate disagrees across environments (the discovered structure wins in Env I and IV; the true graph wins in Env III). Every gate is single-seed and is confounded, because the two structures do not face the same set of conflicts. The gate does not yet tell us whether a structure learner is worth building.
  5. A concrete bottleneck is now visible. In Env I and Env IV the planner's absolute utility is negative — the planner does worse than doing nothing. The dominant cause is out-of-distribution model exploitation. This is the most actionable next problem.
Glossary

01Terms used in this report

Read this section first. Each term below is grounded in the code. The four "variants" are four ways to build the world model. A world model predicts the next network state from the current state and an action. The planner uses the world model to choose actions.

full
The default world model. It uses the discovered causal structure AND the bounded residual. (structure_source=discovered, residual_enabled=true.)
structure_only
The discovered causal structure, with the residual turned OFF (it contributes exactly zero). This isolates the causal structure. (residual_enabled=false.)
oracle
The world model built from the environment's TRUE adjacency matrix instead of the discovered one, residual off. It is the "perfect graph" reference. It needs no discovery. (structure_source=oracle.)
dense
A plain neural network world model (MLPInference) with no structure and no residual. Its hidden layers are hard-coded to (64, 32), so it is small (about 4k parameters). It is a floor, not a fair rival to the ~1.4M-parameter structured model.
discovered structure
The causal graph the pipeline learns from data in the discover stage. It is a calibrated posterior over graph edges plus a frozen "enumeration graph". Reported as "N state edges" (Env I 13, Env III 21, Env IV 17).
bounded residual
A small, strongly-regularised dense correction added on top of the structured prediction. Its size is clamped (|delta| < 0.25) and it starts at zero. Its purpose is a safety net so a missed true edge stays recoverable — not to replace the structure.
latent confounder
A hidden variable that drives two observed variables at once. Env IV injects a hidden scalar Z into two KPIs. No edge between them exists in the true graph, so a graph over only the observed variables is misspecified there by construction.
OOD (out of distribution)
The evaluation uses parameter ranges the model did not train on (evaluation_param_ranges=ood). It tests generalisation, not memorisation.
MSE / NLL
MSE = mean squared error of the predicted next state (lower is better). NLL = negative log-likelihood of a mixture over ensemble members (lower is better; it also penalises bad uncertainty).
residual_mag_ratio
A diagnostic: the size of the residual relative to the structured mean. It is a collapse warning (alert at 0.25–0.28). It is NOT the attribution answer.
dMSE_residual
The primary residual metric: the paired change in MSE when the residual is removed from the full model, on the same data. Positive means the residual helps. It is 0 for the other variants by construction.
QACM
The planner read by the gate. It searches all candidate actions for one conflicting control parameter and picks the action with the lowest QoS cost.
utility / satisfaction
Utility is a KPI z-score: (value − mean)/std. So utility = 0 means the KPI sits at its average, which is what a random or no-op action gives. Negative utility is worse than no-op. Satisfaction rate is the fraction of decisions whose utility clears a threshold.
quantile / mean
Two ways to combine the ensemble's predictions in the planner. quantile is risk-averse (it plans against a bad-case member). mean is risk-neutral.
2×2 gate
The decision-level experiment: {discovered, oracle} × {quantile, mean}, scored by QACM utility. It asks whether a better graph changes the mitigation decision, not just the prediction.
Context

02What changed from the conference paper to feat/v2

The conference architecture was a proof of concept. The team reset the goal from "beat the conference" to "solve the O-RAN xApp conflict problem". feat/v2 keeps the idea (causal learning plus a model-based planner) but rebuilds the mechanism. There is no backward compatibility constraint.

Conference (proof of concept)

  • Structure: one binary graph from a hard CMI threshold (Env I 0.16, Env II 0.20).
  • Graph use: the SAME graph both enumerates conflicts and masks the world model.
  • Dynamics: max-pool over masked and full conditionals; per-parent identity is lost.
  • A missed edge is an irreversible hole in the model.
  • Planning: one world model; pick the least-QoS-cost action.
  • Driving failure (Env I, seed 45): the graph missed a true edge and added a spurious one; the causal planner scored pooled utility 0.148 against the plain network's 0.249 — even though the causal world model had lower MSE (0.062 vs 0.078).

feat/v2 (this study)

  • Structure: a calibrated posterior over graphs; a separate frozen graph for enumeration.
  • Graph use decoupled: the crisp graph enumerates; sampled structures mask the model.
  • Dynamics: structure-conditioned ensemble that keeps per-parent identity, plus a bounded, zero-initialised residual so a missed edge stays recoverable.
  • Planning: robust return over ensemble members (risk-averse quantile) plus a disagreement signal.
  • New: a decoupled discover stage — the pipeline now runs from scratch on any environment (before, only an old checkpoint made it work).
  • New: attribution infrastructure — two knobs (structure_source, residual_enabled) and a planner-free prediction harness that produce the four variants and the metrics in this report.

What was removed

One commit removed the conference hard-mask architecture and its regression lock (net −5,581 lines). The removed parts:

  • The hard_mask dynamics mode and the max-pool prediction path; structure_conditioned is now the only dynamics path.
  • The golden regression lock (the fixed-output tests and their four JSON fixtures).
  • The P0 "corruption sweep" harness — it corrupted a single binary graph, which the new sampled posterior no longer uses; re-pointing it would be a redesign.
  • The CMI machinery was KEPT on purpose — the posterior bootstrap and the new discovery stage depend on it.
Still present, not yet cleaned: scripts/ablation_sweep.py still holds dead conference recipes (hard_mask, soft_mask) that no longer resolve against any config field. This script is not on the current path. Reframe it only after the decision-level question is settled.
An earlier concern, now resolved: an overnight run reported a residual contribution of 0.28, over the 0.25 alert — the worry that the causal structure was not earning the gain. The corrected attribution run puts it at 0.25 (Env I), under the alert, and Env III/IV show the residual is net harmful. The structure, not the residual, carries the prediction.
Environments

03The four environments and how they differ

Each environment is a simulated O-RAN control problem. It has control parameters (NCPs, labelled P0, P1, …) and key performance indicators (KPIs, labelled K1, K2, …). An action sets one control parameter; the environment maps the parameters to the KPIs. A "conflict" is when several xApps want to move a shared parameter in different directions. The four environments get larger and harder from I to IV. Env IV adds a hidden confounder.

Env I — smallest, clean

7 params, 4 KPIs. Two parameters use a wide (0–300) scale, the rest a tight (0–3) scale. KPI responses are near-delta Gaussians. P0 drives both K1 and K2 with opposed centres, so it is a shared-parameter conflict. Two previous-step KPI→KPI edges (K1→K3, K2→K4).

Env II — dense parameter sharing

8 params, 6 KPIs. One xApp owns a KPI pair (K41, K42) that share parameters with opposed offsets. K5 is the only minimise KPI. Dense P0/P1 sharing across K1, K2, K3, K5. No KPI→KPI edges.

Env III — noise + a real KPI chain

9 params, 7 KPIs. Adds observation noise (0.05) and a genuine two-hop KPI→KPI chain K0→K4→K5. Built to stress causal recovery under noise.

Env IV — the latent confounder (the point of this env)

10 params, 8 KPIs. Keeps Env III's chain and adds a hidden scalar Z ~ Normal(0, 0.30), drawn each step and injected into the observations of K6 and K7 only, with gains [1.0, 0.8]. Z is not a parameter, KPI, or state variable. So K6 and K7 stay correlated after conditioning on every observed variable, yet there is no true edge between them. A correlation graph adds a spurious K6–K7 edge; a causal method that needs a mechanism must reject it. This is the test of whether the method confuses correlation with causation.

In Env IV the discovery keeps the true K0→K4→K5 chain and adds NO edge between K6 and K7, even though the hidden Z makes them correlated. This is the intended demonstration: the method does not confuse correlation with causation. It explains why the discovered graph beats the true observed-node graph out of distribution in Env IV (the true graph cannot model Z at all).

Weak spot Env II recovery is poor

Env II misses 6 of 16 true edges, including the entire parent set of K5, and adds one spurious edge. Dense parameter sharing is hard for the current discovery. Env II was not run in the experiment; this graph is for context.

Method

04Experiment design

The central question is: does the causal STRUCTURE earn its keep, or does the dense RESIDUAL do the work? The study answers it at two levels.

Two levels

  • Prediction level (cheap, first): held-out one-step MSE and NLL on out-of-distribution data. No planning. This isolates the world model.
  • Decision level (the 2×2 gate): QACM planner utility. This asks whether a graph difference actually changes the mitigation decision. A prediction difference need not change a decision, so the direction question is gated on utility, not MSE.

Protocol

  • One shared discovery per environment produces the calibrated posterior and the enumeration graph. The full and structure_only variants consume them.
  • Four variants trained per environment: full, structure_only, oracle, dense.
  • Matched 20k training-step budget on every environment, for a fair cross-environment comparison. (The config default of 50k was treated as a leftover; a matched budget is the fair comparison and the prediction curves were consistent.)
  • Held-out set: 4096 transitions on the OOD range, seed 0.
  • The gate reuses the trained structure_only (discovered) and oracle checkpoints, residual off, and switches only the ensemble aggregator.

Finding Structure earns its keep

structure_only beats the dense floor by 27% / 48% / 67%. The gain grows with complexity. Because dense is a small network, treat this as a floor comparison, not a capacity-matched one (see open issues).

Finding The discovered graph is more robust than the true graph OOD

The discovered structure beats the true adjacency out of distribution by 1.2× / 3.8× / 5.5×. The true graph overfits in range and is overconfident out of range. In Env IV the true observed-node graph cannot represent the hidden confounder, so the discovered graph wins by the largest margin.

Finding The residual is not load-bearing

Env I: the residual adds +11% (structure_only still far above dense). Env III and IV: the residual is net harmful — structure_only beats full, and dMSE_residual is near zero or negative. The structure carries the signal.

Not settled The environments disagree

Two of three environments (I, IV) say the discovered structure beats the true graph on utility. Env III is the lone outlier (the true graph wins by +0.070 on the quantile cell).

Confound Unequal decision sets

The true-graph enumeration always detects more conflicts than the discovered enumeration (I 300 > 270, III 690 > 600, IV 570 > 420). The two structures do not face the same conflicts, so mean utility is not a like-for-like comparison. Paired seeds do not fix this structural confound.

Single seed No confidence intervals

Every gate cell used one mitigation seed. The small Env III gap could be noise. The gate's own rule asks for paired-seed confidence intervals before any claim.

Correction Env I alone was misleading

An earlier note concluded "stop the structure-learner direction" from Env I. Across environments the direction is env-dependent and unresolved. Do not build a structure learner on this evidence, and do not declare it dead.

Risk setting: the risk-averse quantile is best in Env I and III; the mean is best in Env IV (it raised average utility without worsening the tail). So the risk setting is also environment-dependent.
Diagnoses

07Two results that need an explanation

Why the oracle NLL explodes (566, 137, 70)

The oracle fits the training range almost perfectly (Env I in-range MSE 0.013, graph F1 1.0), so its predicted variance falls to a floor and it becomes overconfident. On the OOD range its mean drifts, but its variance stays pinned, so the NLL explodes. The oracle ensemble also has zero spread — every member draws the same one-hot true graph — so the mixture cannot widen. This is expected behaviour of a degenerate, overconfident model on OOD data, not a bug. Treat the oracle as an MSE reference only; drop its NLL from any ceiling comparison.

Why the absolute utility is often negative

Utility = 0 is the no-op reference. In Env I and Env IV the planner scores negative — it does worse than doing nothing. For Env I the numbers are: QACM −0.11, a random action +0.24, the best single-parameter action +0.94. So the planner leaves about 1.05 of utility per decision on the table. The dominant cause is out-of-distribution model exploitation: the planner trusts the world model, which errs on the OOD range, and picks confidently-wrong actions. Secondary causes: the planner objective is indifferent to utility once a decision looks "satisfied"; about 22% of conflicts are genuinely infeasible (shared parameters with opposed optima); and one KPI threshold is essentially unreachable, which caps the satisfaction rate.

Decisions

08Decisions made and alternatives considered

Decision · Gate on utility, not MSE

A prediction difference need not change a mitigation decision. The direction question is therefore decided by the 2×2 utility gate. Alternative rejected: deciding from MSE alone.

Decision · Do NOT adopt an off-the-shelf DAG structure learner (DiBS / NOTEARS)

Our graph is a temporal t→t+1 transition graph. DAG learners assume instantaneous DAGs; acyclicity would wrongly forbid valid lagged reciprocal effects. Env IV's latent confounder also breaks a DAG over observed nodes. Alternative kept open: a dynamic-parent-mask posterior, but only if the gate shows a real oracle advantage.

Decision · Matched 20k training budget across environments

A matched budget gives a fair cross-environment comparison. Alternative rejected: the config default of 50k, treated as a leftover; the prediction curves were consistent at 20k.

Decision · Keep the risk-averse quantile as the default

The mean helped only in Env IV. For a safety-relevant RIC, risk aversion is more defensible. Alternative kept open: a calibrated CVaR objective if the mean proves better with CIs.

Engineering · Reduce MCTS budget for the gate

The gate reads only QACM, but evaluate runs four planners; MCTS at 3000 simulations cost about 37 s per action. Cutting it to 2 via a config override made the gate run in about 40 minutes instead of about 4 hours. QACM is unchanged (each planner reseeds independently). No code change.

Open issues

09Open issues and risks

High Negative absolute utility (Env I, IV)

The planner does worse than no-op. Dominant cause: OOD model exploitation. This is the most concrete, environment-general problem to fix next.

High The utility gate is confounded

The two structures face different conflict sets (unequal decision counts). Until a same-decision-set comparison exists, no oracle-vs-discovered utility claim is trustworthy.

Medium All gate results are single-seed

No confidence intervals. Env III's small oracle advantage may be noise.

Medium Dense is a floor, not a fair rival

The dense network has about 4k parameters, roughly 190× smaller than the structured model. The 27–67% gains are versus a floor. A capacity-matched dense network (wire config into the hidden layers) is needed for a fair claim.

Low Dead conference recipes remain

ablation_sweep.py still holds hard_mask / soft_mask recipes that no longer resolve. Not on the current path; reframe later.

Low The oracle ensemble is degenerate

The oracle draws one fixed structure, so its uncertainty is meaningless. Its risk-averse quantile collapses to its mean. Fine for an MSE reference; not usable as a probabilistic ceiling.

Open questions

10Open questions for the team

  • Is the Env III oracle advantage real, or is it the decision-set confound and seed noise? Only a same-decision-set, paired-seed gate can answer this.
  • Does the discovered-beats-true-graph OOD result hold under a capacity-matched dense network and more seeds? If so, it is the paper's headline.
  • Why does the true graph over-detect conflicts? Is the enumeration graph too dense, or is the discovered enumeration missing real conflicts?
  • Is negative absolute utility a planner problem, a world-model OOD problem, or a metric problem? The in-distribution eval (below) separates the first two.
  • Should the risk setting (quantile vs mean) be chosen per environment, or fixed for safety?
  • For Env IV, is the right tool a latent-variable causal model (ADMG), given a DAG over observed nodes is misspecified there?
Future directions

11Recommended next steps (ranked)

  1. Fix the negative-utility bottleneck first.

    Start with the free, reversible lever: turn on the existing planner pessimism knobs (disagreement_penalty / ood_threshold) so the planner avoids actions where the ensemble disagrees (out-of-distribution). Config only, no retrain. Confirm with one in-distribution eval (predicted: utility jumps toward the +0.24 to +0.94 band if OOD model error is the cause).

  2. De-confound the utility gate.

    Add paired-seed confidence intervals AND a same-decision-set comparison (score both structures on the SAME conflicts). Only then compare oracle vs discovered utility.

  3. Add a capacity-matched dense baseline.

    Wire the config dimensions into the dense network's hidden layers, so the structure claim is against a fair rival, not a 4k-parameter floor.

  4. Lead the paper with the prediction-level generalisation.

    "The discovered causal structure earns its keep and generalises out of distribution better than the true graph, most under a latent confounder" is the strong, clean, multi-env result.

  5. Decide the structure-learner direction only after the de-confounded gate.

    If a real oracle advantage survives, prototype a dynamic-parent-mask posterior (not an off-the-shelf DAG learner). If not, close the direction.

12Provenance, commands, and caveats

How to reproduce (per environment)

discoveruv run python -m cdd_oran.cli discover --config configs/env_<e>_cdl.yaml
train full… cli train --config env_<e>_cdl.yaml --set train.total_steps=20000
train structure_only… --set model.residual_enabled=false
train oracle… --set model.structure_source=oracle --set model.residual_enabled=false

attributionuv run python scripts/attribution_eval.py --run <4 dirs> --device cuda --n-transitions 4096 --require-full-set
gatecli evaluate --run <dir> --config <copy with aggregator + mcts n_simulations=2> ; then scripts/gate_2x2.py
Note on the gate command: evaluate does not accept --set; the aggregator and the reduced MCTS budget are applied through a copied --config file.

Caveats on the numbers

  • All results are single-seed (train seed fixed per env config; gate mitigation seed 0). CUDA is not bit-reproducible.
  • The dense baseline is a floor, not capacity-matched.
  • The oracle NLL is not a valid ceiling (degenerate ensemble); use oracle MSE only.
  • The utility gate compares different decision sets across structures; treat the direction claim as provisional.
  • Env II was not run (Env III and IV are the harder, unseen test; Env IV has the latent confounder). The conference numbers quoted are from the project's earlier records, mostly single seed.
