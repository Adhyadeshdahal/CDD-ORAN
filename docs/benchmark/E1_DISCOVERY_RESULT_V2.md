## The method change (v1 -> v2), in one line

v1 scored each edge by the **absolute standardized OLS coefficient** `|beta|` and thresholded the
**pooled** score vector with one global `largest_gap` cut. v2 scores each edge by the **magnitude of
the partial correlation** of that input with the target, *controlling for all other candidate
inputs*, and thresholds **per target** with `largest_gap(floor = 0.0)`. Partial correlation
normalizes by *residual* variance instead of total output variance, removing the multi-parent
`sd(y)` deflation that pushed v1's KPI->KPI scores below the global cut.

Per-target thresholds `largest_gap(scores[j, :], floor = 0.0)` = **[0.500, 0.500, 0.500, 0.500]**

## Three-arm one-step prediction: MSE parity by construction (mask-identity)

This phase does **not** retrain the three-arm envelope. It does not need to, and the parity claim
below is a **construction result**, clearly labelled as such — **not** a fresh measurement, and no
v2 MSE numbers are fabricated.

The discovered arm shares the oracle arm's exact per-output MLP, rows, train IDs, model config, and
weight seed (protocol §6); the *only* thing that ever differed between them is the input mask. v2's
discovered mask is now **bit-for-bit identical to the oracle mask** (verified above, all seeds).
Training is deterministic (Plan 004 recorded zero variance across seeds). Two arms with an identical
architecture, identical data and train IDs, identical config and weight seed, and now an identical
mask are the **same model**; their held-out one-step MSE is therefore **equal by construction**.

For contrast, v1's measured three-arm held-out MSE (`E1_DISCOVERY_RESULT.md`, n = 192) was:

| arm | v1 test MSE |
|-----|-------------|
| oracle | 4.253e-07 |
| dense | 1.433e-06 |
| discovered (v1) | 1.036e-02 |

In v1 the discovered arm was ~4 orders of magnitude worse than oracle **because it missed the two
KPI->KPI parents** — its K2/K3 heads could not see K0/K1, so they could not represent
`K2 = P2 + 0.5·K0` or `K3 = P3 + 0.5·K1`. In v2 that gap closes **entirely and by construction**:
discovered mask == oracle mask, so discovered arm == oracle arm, so
`MSE(discovered) = MSE(oracle)` — the ~4-orders-of-magnitude v1 penalty is removed because the cause
of it (the missing KPI->KPI edges) is gone.

## Interpretation stance (locked) and the noiseless caveat

Stated plainly, not dressed up (per protocol §9): E1 is the **noiseless linear recovery control**.
Partial correlation, by residualizing out the other inputs, drives every true direct parent to
`|rho| ~ 1` and every non-parent to exactly `0`; `FROZEN_FLOOR = 0.0` lets the per-target
`largest_gap` cut land at the `0 -> signal` boundary (~0.5), so single- and multi-parent targets
recover alike without a floating-point tie. The near-perfect separation is a **property of the
control** — a noiseless linear system read with the right conditioning — not a hard-won empirical
result. Green E1 means the label-free pipeline recovers structure **when it is recoverable**, which
is exactly E1's intended role and what unblocks interpreting E2+. No noise was added to E1 to
manufacture difficulty; noise and nonlinearity belong to E2+.

## Limitations and next step

- The result is specific to the linear, noiseless E1 control. It says nothing about discovery under
  process noise, nonlinearity, or unobserved confounding — those are the E2+ regimes, where partial
  correlation is not expected to give a clean `0`/`1` separation and discovery is non-trivial.
- The three-arm prediction parity is a construction result from mask-identity, not a fresh
  measurement; if a directly-measured v2 three-arm envelope is later wanted, it is a separate
  (heavy) run and would, by the argument above, reproduce `MSE(discovered) = MSE(oracle)`.
- The natural next step is E2+ (noisy / nonlinear), where the label-free rule must be re-evaluated
  and is expected to be genuinely harder.

The result is reported as the frozen method produced it; it was not adjusted after E1 truth was
inspected. The two protocol revisions were made **before** first execution to fix defects that would
have prevented the method from running or from implementing its own stated intent (see the protocol's
Revision history), never after seeing a recovery number.
